1. Fix Scanned-PDF Completeness

Goal: Prevent the system from silently ignoring later pages in scanned documents.
Main implementation areas: backend/rag/parsing.py, backend/agents/orchestrator.py

How to implement

1. Detect which PDF pages contain extractable text and which require rasterization/OCR/vision.
2. Process every page; use 3-4 page batches per vision call instead of a 4-page total cap.
3. Merge page outputs while preserving filename, page number, extraction method, and confidence.
4. Persist each page result as independent evidence before it enters reasoning.

Done when

A 20-page scanned PDF can be processed end-to-end and every cited fact maps to the correct page.

2. Fix Evidence Provenance

Goal: Ensure every fact points to the exact source file/page/region from which it came.
Main implementation areas: backend/agents/orchestrator.py, backend/evidence/models.py

How to implement

5. Remove any fallback that attributes visual evidence to task.files[0].
6. Create EvidenceItem fields for source_id, filename, page, bbox, modality, confidence, extraction_model, and

     source_sha256.
7. Generate one evidence item per visual/text extraction, not one merged anonymous blob.
8. Propagate evidence IDs into downstream prompts and verifier inputs.

Done when

Uploading multiple files never causes a finding from one file to be attributed to another.

3. Replace Regex Citations with Typed Evidence

Goal: Make verification structural instead of dependent on citation string patterns.
Main implementation areas: backend/evidence/citations.py, backend/verification/citation_verifier.py

How to implement

9. Define typed evidence categories: DOCUMENT, FILE, VISION, CALCULATION, EXECUTION, HUMAN.
10. Assign stable IDs such as S12, F4, V9, C3, X2, H1.
11. Represent claim-to-evidence links as structured objects.
12. Use rendered citation labels only as UI; verification should operate on IDs and objects.

Done when

Vision, calculation, sandbox, file, document, and human evidence are all verifiable through one
interface.

5. Move Code Execution to a Rootless Container Sandbox

Goal: Turn application-level safeguards into OS-enforced isolation.
Main implementation areas: backend/sandbox/ast_guard.py, backend/sandbox/container_runner.py,
backend/sandbox/resource_limits.py

How to implement

17. Keep the current AST security scanner as the first layer.
18. Run generated Python inside rootless Podman or equivalent isolated containers.
19. Use --network none, read-only root filesystem, non-root UID, cap-drop ALL, no-new-privileges,

     CPU/memory/PID/file-size/time limits.
20. Mount only temporary input/output directories; never mount host home, project root, SSH keys, or

     container sockets.
21. Register stdout, stderr, exit code, resource use, and policy result as execution evidence.

Done when

Known malicious snippets cannot access the network, host filesystem, privileged processes, or
uncontrolled resources.

6. Implement Enforceable Zero-Egress

Goal: Make sovereignty a control that the OS enforces and the UI can prove.
Main implementation areas: backend/security/network_guard.py, backend/security/egress_monitor.py,
backend/security/sovereignty.py

How to implement

22. Enforce network isolation at the sandbox/container layer.
23. Add host firewall/nftables rules appropriate to your deployment mode.
24. Monitor runtime connection attempts and count blocked attempts, outbound connections, DNS queries, and

     bytes sent.
25. Emit task-scoped security events and expose the metrics through the API.
26. Create automated tests that attempt HTTP, DNS, raw socket, and subprocess-based network access.

Done when

A malicious network attempt is blocked and the task proof shows zero successful external transmission.

7. Build a Deterministic Engineering Calculation Engine

Goal: Move critical calculations out of free-form LLM arithmetic.
Main implementation areas: backend/engineering/registry.py, backend/engineering/corrosion.py,
backend/engineering/pressure.py, backend/engineering/piping.py

How to implement

27. Create a versioned formula registry.
28. Start with formulas required by your strongest demo, such as corrosion rate and remaining life.
29. Require the LLM to request a formula by ID and provide evidence-backed inputs.
30. Execute formulas deterministically and register the result as calculation evidence.
31. Store formula ID, version, inputs, output, units, and supporting evidence IDs.

Done when

The same inputs always produce the same result, and each numeric result has reproducible provenance.

8. Add Unit-Aware Calculations

Goal: Catch dimension errors and normalize engineering quantities.
Main implementation areas: backend/engineering/units.py

How to implement

32. Integrate a local units library such as Pint.
33. Parse values into quantity + unit objects.
34. Normalize compatible units before formulas execute.
35. Reject dimensionally invalid operations such as pressure plus thickness.
36. Preserve original and normalized units in the evidence record.

Done when

Unit conversion tests pass and dimensionally invalid calculations are refused before execution.

9. Build Claim-Level Verification

Goal: Verify each material statement rather than only checking the final answer as a blob.
Main implementation areas: backend/verification/claim_extractor.py,
backend/verification/evidence_mapper.py, backend/verification/numeric_verifier.py,
backend/verification/verifier.py

How to implement

37. Extract atomic claims from the drafted answer.
38. Classify claims as factual, numerical, engineering conclusion, recommendation, or procedural.
39. Map each claim to supporting evidence IDs.
40. Independently recompute numerical claims when a deterministic formula exists.
41. Mark claims as VERIFIED, SUPPORTED, UNSUPPORTED, CONFLICTED, or NEEDS_REVIEW.
42. Prevent unsupported high-impact claims from passing the policy gateway.

Final Build Order - One-Line Checklist

 1-4 Foundation: completeness, provenance, typed evidence, evidence ledger.
 5-6 Security core: rootless sandbox and enforceable zero-egress.
 7-10 Correctness: deterministic formulas, units, claim verification, contradictions.
 11-15 Knowledge/security ingestion: hybrid RAG, revision control, injection defense, file guard, DLP.
 16-18 Industrial intelligence: P&ID extraction, graph reasoning, visual proof.
 19-23 Governance transparency: benchmark-aware routing, model integrity, policy/routing explorers.
 24-28 Proof and authority: Proof Mode, approval, signed audit, sovereignty certificate, reproducibility.
 29-34 Hardening and demo: recovery, refactor, evaluation, red-team, dashboard, three golden demos.
 35-36 Deployment maturity: enterprise identity and offline installer.

Do Not Prioritize Yet

 PostgreSQL/pgvector migration unless current storage is a real blocker.
 Redis, Kafka, Kubernetes, distributed workers, or service sprawl only for architecture optics.
